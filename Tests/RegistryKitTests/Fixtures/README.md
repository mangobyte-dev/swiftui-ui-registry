# Migration oracle fixtures

`schema.json` and `preset_vectors.json` are byte copies of the canonical `Registry/schema.json` and the shared codec vectors in `Registry/preset_vectors.json`, which the website's TypeScript and the Showcase's Swift also reproduce. `fixturesMatchCanonicalContracts` rejects drift between the copies and the originals. `preset-vectors-check.ts` runs `Website/lib/preset.ts` under `node --experimental-strip-types` for `websiteCodecReproducesEveryVector`

`validation-cases.json` records 45 distinct calls made by the unchanged `test_validation.py` suite at 0d353ed. Each entry carries the test name, registry files, scope, and the Python validator's exact ordered issues. The Swift tests load the files into an in-memory filesystem, parse the real validate command, and compare its exit status and both output streams. A malformed fixture cannot pass by merely throwing an unrelated error

`diff-cases.json` records 106 Python `difflib.unified_diff` results with three context lines. The cases cover insertions, deletions, replacements, repeated lines, empty files, missing final newlines, CRLF, other splitlines boundaries, and SequenceMatcher's autojunk threshold. The random cases use a fixed Python seed of 42

The inline installation, merge, and conflict directory snapshots in `Commands.swift` and `InstallerSafetyTests.swift` were produced by `Scripts/install.py`. They include every directory, owned source byte, receipt byte, base byte, and conflict artifact. `PresetCommandSnapshots.swift` takes its expected text from `Scripts/preset.py`

`Scripts/check_swift_parity.py` was the subprocess proof for Phase A and Phase B, removed with the Python path in Phase C (last run at `41c2bd8`, 1,184 comparisons). It copied the registry into a temporary clone, compared stdout, stderr, and exit status, then compared complete destination trees without normalizing file contents. Its interoperability cases started both destinations with a Python receipt, then with a Swift receipt, and updated each with both tools

`RegistryContractTests.swift`, `MCPContractTests.swift`, and `PresetContractTests.swift` carry the assertions ported from the former Python suites that read the real registry: native seams, the value gate, the token consumer contract, block resolution order, receipt provenance, plan and diff output over real items, search ranking and aliases, the MCP tools over the real catalog, and the preset spellings

`MCPTests.swift` pins the seven successful tool responses as exact inline wire snapshots generated by the Python server over the same `example` fixture. Its protocol and refusal snapshots cover parse errors, notification silence, unknown methods and tools, invalid arguments, and unknown items. Persistent metadata reload and home expansion use injected effects

`GeneratorTests.swift` parses all three real generator commands, snapshots their output, checks orphan cleanup and index-name refusal, and regenerates the full repository into an in-memory destination. It compares every catalog page, both Showcase manifests, website JSON, and all copied images byte for byte. The publishing tests from the three Python generator test modules are also represented as explicit usage, ordering, recipe, source, and screenshot assertions
